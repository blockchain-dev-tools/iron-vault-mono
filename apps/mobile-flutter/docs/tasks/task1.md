### 设计原则

1. **渐进式**：初期结构简单够用，后续可根据需要扩展
2. **协作友好**：AI 能理解、人类能阅读，模板减少沟通成本
3. **与项目架构对齐**：文档分类与 `AGENTS.md` 中定义的模块（Rust SDK、BLE、屏幕流、APDU 等）保持一致
4. **学习友好**：为非 Flutter 开发者提供清晰的学习路径，降低进入壁垒

### Agent 自我进化机制

Agent 的"自我进化"是指每次工作产出的知识能被后续的 Agent 自动继承，而不需要从头学习。

#### 进化层次（按成熟度从低到高）

| 层次 | 机制 | 说明 |
|---|---|---|
| **L0 - 静态指南** | `AGENTS.md` 手写维护 | 当前状态，知识不自动沉淀 |
| **L1 - 活文件** | Agent 完成任务后自动追加新模式到 `AGENTS.md` | 低投入高收益，推荐初期启用 |
| **L2 - 决策记录** | `docs/adr/` 记录每次架构决策（背景、选项、理由） | 当需要做类似选择时直接检索复用 |
| **L3 - 历史检索** | 启动任务前用 `session_search` 搜索历史会话 | 利用平台能力，无需额外文件 |
| **L4 - 项目技能** | 封装自定义 skills（如 `iron-vault-screen`） | 最高级，将隐性知识编码为可执行引导 |

#### 初期推荐方案（L1 + 模板信号）

**A. 允许 Agent 写 AGENTS.md**

- 任务完成后，自动追加新发现的模式和已完成状态
- 维护一个"已实现清单"（如已完成哪些屏幕、哪些链）
- 记录代码风格偏好（review 中纠正过的写法）

**B. 模板中的"进化信号"**

在任务模板中增加一个区块，Agent 填写后自动合并到 AGENTS.md：

```markdown
### 本次实现中发现的新知识
- [新的 Flutter 陷阱 / 平台差异]
- [之前 AGENTS.md 未覆盖的模式]
- [建议更新的配置 / 规则]
```

**C. 自动化闭环**

```
完成任务 → 运行 review → 提取"下次要注意什么" → 追加到 AGENTS.md
```

#### 与 `docs/` 目录结构的关系

- 决策记录建议存放于 `docs/adr/`（后续结构设计的一部分）
- 技能文件建议存放于 `.opencode/skills/`（平台原生支持）
- 每次进化产出的知识更新到 `AGENTS.md`，作为全局入口

### 待明确问题

以下是需要向用户确认的关键问题：

1. **Flutter 经验程度**：是完全零编程经验，还是有一定其他语言（如 JavaScript/Python）基础？这会影响学习路径的起点。
2. **Rust 知识**：是否了解 Rust？加密 SDK 部分涉及 Rust 开发，是否需要纳入 Rust 学习计划？
3. **开发环境**：
   - 使用什么操作系统？（影响 Flutter 环境搭建和 Android/iOS 构建）
   - 是否有 Android 或 iOS 真机用于测试 BLE 功能？
4. **目标平台优先级**：优先 Android 还是 iOS，还是两者同时？BLE 外设模式在 Android 上需要额外配置。
5. **时间规划**：希望以什么节奏推进？每天/每周能投入多少时间？
6. **任务交互风格**：
   - 倾向于我主动推进（"你觉得下一步做什么"），还是你指定具体任务？
   - 偏向详细的技术解释，还是简洁的执行指令？
7. **对 iron-vault-mono 的熟悉程度**：是否已经阅读过原项目的代码？还是希望我在后续过程中逐步讲解？

### 我的一些建议

1. **学习路径建议**：推荐先完成 Dart 语言基础（1-2天）→ Flutter Widget 基础（3-5天）→ 然后边做边学，通过实际任务驱动学习效果更好。
2. **文档驱动开发**：每次实现功能前，先在 `docs/tasks/` 下写任务描述 → 在 `docs/discusses/` 下讨论方案 → 达成一致后开始编码。
3. **先搭建骨架**：初期先完成 Flutter 项目初始化、路由框架、主题系统等基础结构，让你快速看到可运行的 App，增强信心。
4. **双轨并行**：Flutter UI 开发和 Rust SDK 开发可以并行推进，互不阻塞。
