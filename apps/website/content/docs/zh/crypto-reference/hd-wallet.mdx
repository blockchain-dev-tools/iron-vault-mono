# 分层确定性钱包

想象你有一个比特币钱包。你在一个地址上收到钱，然后希望下次交易时使用一个新地址。没有一个系统化的方案，你需要：

1. 生成一个新的私钥
2. 将这个私钥安全备份
3. 记住你用过哪些密钥

现在把这个场景扩展到 10 个地址，再到 100 个，还要同时覆盖以太坊、Solana 和比特币。逐个管理私钥变得完全不可行。

**分层确定性钱包（HD Wallet）** 用两个核心思想解决了这个问题：*确定性* 和 *分层性*。

---

## 确定性：一个种子，无限密钥

确定性意味着 **同一个起始秘密始终产生同一序列的密钥**。与随机生成密钥（必须逐个备份）不同，HD 钱包从一个单一的 **种子（seed）** 派生所有密钥——通常是 64 字节的随机数据。

```
种子 → 主密钥 → 子密钥 1 → 孙密钥 A
              → 子密钥 2 → 孙密钥 B
              → 子密钥 3 → 孙密钥 C
```

只需备份种子一次，就能恢复从中派生的每一个密钥。如果你的手机丢失了，仅凭种子即可恢复整个钱包。

---

## 分层性：树状结构

"分层"意味着密钥按树状结构组织。父密钥可以派生多个子密钥，每个子密钥又可以派生自己的子密钥，以此类推。这个结构由 **BIP32**（比特币改进提案 32）定义，它正是 HD 钱包的底层标准。

为什么要用树状结构而不是扁平列表？

- **组织管理**——不同的分支用于不同的目的（收款地址、找零地址、不同区块链）
- **选择性暴露**——你可以共享一个公钥父密钥（"xpub"）而不暴露其下的私钥，从而创建一个"只观察"钱包，可以查看交易但不能花费
- **备份不变性**——备份一个节点就备份了其下的所有内容

---

## 密钥派生：工作原理

BIP32 定义了一个 **子密钥派生（CKD）** 函数。给定父密钥和一个索引号，它产生一个子密钥对：

```
子密钥 = CKD(父密钥, 索引)
```

派生过程使用 HMAC-SHA512 将父密钥的私钥和链码与子索引混合，生成 64 字节。左 32 字节成为子密钥的私钥（加上父密钥的私钥后），右 32 字节成为子密钥的链码。

### 硬化派生 vs 普通派生

BIP32 定义了两种子密钥派生方式：

| 类型 | 表示法 | 索引范围 | 特性 |
|---|---|---|---|
| **普通派生** | `0`, `1`, `2`... | 0 到 2³¹−1 | 给定父 xpub + 子索引，可以计算子 xpub |
| **硬化派生** | `0'`, `1'`, `2'`... | 0' 到 2³¹−1'（第 31 位置位） | 需要父私钥，仅有 xpub 不够 |

硬化派生使用父密钥的 **私钥**（而非公钥）作为 HMAC-SHA512 的输入，产生的子密钥与父密钥的公钥链完全无关。这是一个安全边界：即使有人知道你的父 xpub，也无法派生硬化的子密钥。

**最佳实践**：在树的前几层（路径、币种类型、账户）使用硬化派生，在地址索引层使用普通派生。

---

## 为什么 HD 钱包胜出

在 HD 钱包出现之前，每个地址都是一个独立的随机密钥。备份意味着记下每一个私钥——对于实际使用来说完全不现实。HD 钱包将备份简化为 **一个助记词**，这就是为什么每个现代钱包（MetaMask、Ledger、Phantom、OKX Wallet）都使用它们。

整个生态系统——BIP32 用于密钥树、BIP39 用于种子编码、BIP44 用于路径标准——于 2013–2014 年设计至今，并且一直是自我托管的基石。
