## 概述

IRON Vault 在 BLE 传输层完整模拟了 Ledger Nano X 的行为。OKX Wallet、MetaMask 等宿主应用在 BLE 扫描时，会通过特定的 GATT 服务 UUID 识别 Ledger 设备，并在服务发现阶段验证各特征的 UUID。**UUID 必须与真实设备完全一致** — `@ledgerhq/hw-transport-web-ble` 在源码中硬编码了这些 UUID，任何偏差都会导致宿主应用在服务发现阶段直接忽略该设备。

Android 端使用 `BluetoothGattServer`（API 21+）充当 GATT 外设，并通过 `BluetoothLeAdvertiser` 广播服务 UUID，使宿主应用能够扫描到设备。

---

## UUID 列表

以下五个 UUID 定义于 `LedgerBleConstants.java`，必须逐字节复制，不可有任何改动。

| 名称 | UUID | 用途 |
|------|------|------|
| **Service** | `13d63400-2c97-0004-0000-4c6564676572` | 根 GATT 服务，宿主扫描此 UUID |
| **Notify** | `13d63400-2c97-0004-0001-4c6564676572` | 设备 → 宿主，承载响应 APDU 帧 |
| **Write** | `13d63400-2c97-0004-0002-4c6564676572` | 宿主 → 设备，承载请求 APDU 帧（带响应） |
| **WriteCmd** | `13d63400-2c97-0004-0003-4c6564676572` | 宿主 → 设备，请求帧（无响应，Write Without Response） |
| **CCCD** | `00002902-0000-1000-8000-00805f9b34fb` | 标准 Bluetooth 描述符，宿主写入 `0x01 0x00` 以启用通知 |

CCCD UUID（`00002902-...`）是 Bluetooth SIG 分配的标准描述符 UUID，所有 BLE 设备通用。但仍然必须将其作为描述符手动附加到 Notify 特征上 — 缺少此描述符时，Android 会拒绝 `setValue` 调用，宿主将永远收不到通知。

## 特征属性

每个特征需配置对应的 `BluetoothGattCharacteristic` 属性标志和权限标志：

| 特征 | 属性 | 权限 | 备注 |
|------|------|------|------|
| **Notify** | `PROPERTY_NOTIFY` | `PERMISSION_READ` | 必须附加 CCCD 描述符 |
| **Write** | `PROPERTY_WRITE` | `PERMISSION_WRITE` | 宿主期望收到 ATT Write Response |
| **WriteCmd** | `PROPERTY_WRITE_NO_RESPONSE` | `PERMISSION_WRITE` | 无 ATT 响应，用于命令帧 |

Notify 特征上的 CCCD 描述符本身也必须设置 `PERMISSION_READ | PERMISSION_WRITE`，这样宿主才能读取当前通知状态，并写入 `0x01 0x00` 启用通知。

## 广播配置

设备以名称 `"Nano X"` 进行广播 — 与真实 Ledger Nano X 的广播名完全相同。由于 BLE 广播包的有效载荷上限为 31 字节，广播数据和扫描响应分两包发送：

- **广播数据（Advertising Data）** — 包含服务 UUID（`13d63400-2c97-0004-0000-4c6564676572`），宿主依此识别设备
- **扫描响应（Scan Response）** — 包含完整本地名称 `"Nano X"`，在主动扫描时由宿主请求返回

其他广播参数：

| 参数 | 值 | 说明 |
|------|----|------|
| 广播模式 | `ADVERTISE_MODE_LOW_LATENCY` | 最快发现速度，缩短连接建立时间 |
| 发射功率 | `ADVERTISE_TX_POWER_HIGH` | 最大功率，确保可靠连接范围 |
| 超时 | 0（不超时） | 持续广播直到宿主连接 |
| 可连接 | `true` | 必须为 true，仅扫描的设备无法被连接 |

广播通过 `BluetoothLeAdvertiser.startAdvertising()` 启动，GATT 连接断开后自动重启，保持设备始终可被发现。

## CCCD 通知订阅

在任何 APDU 数据从设备流向宿主之前，宿主必须先**启用通知**。具体方法是向 Notify 特征的 CCCD 描述符（`00002902-...`）写入值 `0x01 0x00`（即 `ENABLE_NOTIFICATION_VALUE` 的小端序表示）。

完整流程如下：

1. 宿主发现 Notify 特征
2. 宿主通过 `BluetoothGatt.writeDescriptor()` 向 CCCD 描述符写入 `0x01 0x00`
3. Android 在外设侧触发 `BluetoothGattServerCallback.onDescriptorWriteRequest()`
4. 外设调用 `BluetoothGattServer.sendResponse(GATT_SUCCESS)` 回应
5. 通知就绪 — 设备可通过 `BluetoothGattServer.notifyCharacteristicChanged()` 推送数据帧

若宿主跳过此步骤，或 CCCD 描述符缺失，`notifyCharacteristicChanged()` 将返回 `false`，所有设备响应都会被静默丢弃。

## Android API 与权限

**核心 API：**

```java
// 打开 GATT 服务器
BluetoothGattServer server = bluetoothManager.openGattServer(context, callback);
server.addService(ledgerService); // 包含三个特征的 BluetoothGattService

// 启动广播
BluetoothLeAdvertiser advertiser = bluetoothAdapter.getBluetoothLeAdvertiser();
advertiser.startAdvertising(settings, advertiseData, scanResponse, advertiseCallback);
```

**AndroidManifest.xml 所需权限：**

| API 级别 | 所需权限 |
|----------|----------|
| API 21–30 | `BLUETOOTH`、`BLUETOOTH_ADMIN`、`ACCESS_FINE_LOCATION` |
| API 31+（Android 12+） | `BLUETOOTH_ADVERTISE`、`BLUETOOTH_CONNECT` |

在 API 31+ 上，`BLUETOOTH_ADVERTISE` 和 `BLUETOOTH_CONNECT` 属于运行时权限，必须在调用任何 BLE API 之前通过 `ActivityCompat.requestPermissions()` 申请。旧版 `BLUETOOTH` 和 `BLUETOOTH_ADMIN` 权限在此版本已不再适用。
